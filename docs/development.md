## 关键踩坑与解决方式

### 1. 不能把随机切分当作时间场景验证

交易数据按时间切分，训练集拟合预处理，验证集选择阈值，测试集只在受控入口评估。这样可以避免未来信息通过随机切分泄漏到训练过程。

### 2. 模型分数不能直接称为概率

当前 LightGBM 使用固定参数和类别权重，输出没有经过概率校准。因此文档和 API 统一称为模型分数，不把它描述为欺诈概率。

### 3. 真实数据和模拟数据必须分开描述

模拟数据用于验证工程闭环和确定性；IEEE-CIS 是公开匿名竞赛数据，只用于研究和基线复现。两者都不能推出真实银行生产效果。

### 4. 模型 bundle 必须先校验再服务

服务启动前校验 bundle、政策和特征契约的冻结摘要。缺失、篡改或不匹配时安全失败，不自动下载或替换模型。

### 5. Docker 演示和质量门禁不是同一件事

质量门禁覆盖静态检查、回归和输入校验；Docker 演示还需要本地 Docker 引擎、端口和授权 bundle。CI 通过不能自动等价于本机 Docker 端到端通过。

### 6. 服务默认只能本机访问

当前服务没有认证、限流和 TLS。默认只监听回环地址，不能直接用于公网部署。

## 维护约定

- 新增功能先更新对应的配置、测试和文档，再更新 README 的使用入口。
- 不把真实交易数据、模型 bundle、凭据或运行时数据库提交到 Git。
- 变更模型、政策、特征契约或存储语义时，必须更新对应的冻结摘要和回归证据。
- 修复历史结论时，在 WORK_LOG.md 追加更正记录，不改写原始记录。
- README 只保留用户运行所需信息；实现细节、取舍和过程放入 docs/。

## 后续候选项

以下是候选方向，不代表已经承诺实现：

- 增加认证、TLS、限流和更严格的部署配置；
- 将默认存储从本地 SQLite 扩展到适合部署的数据库；
- 增加模型校准、漂移监测和再训练流程；
- 补充更多历史版本 bundle 的迁移和兼容策略；
- 增加更完整的服务端到端和 Docker CI 验证；
- 在保持证据校验和失败关闭的前提下扩展调查辅助能力。

这些方向实施前应先更新 PROJECT_PLAN.md 和相应边界说明。
